# Product State

Status: CURRENT TARGET

## Current Goal

- The current goal is a genuinely usable initial public launch.
- The initial release should provide enough real value that external users can actually use Playhoot.
- The launch target is not merely a technical demo or internal prototype.

## Primary Initial Audience

- Education/classroom use is the primary initial product focus.
- Teachers creating interactive activities are the most important initial creator audience.
- Playhoot is not permanently restricted to education.
- Other social-game use cases may exist later.

## Initial Release Product Loops

### Creator

- Sign in using Google.
- Create a game.
- Use AI-assisted game creation.
- Optionally begin from a template.
- Preview or test the generated game.
- Refine the game.
- Publish the game.

### Public Content

- Public games can be discovered and searched.
- A user can create or play a session using an appropriate public game even if they are not its original creator.

### Host

- Choose an appropriate game.
- Create and start a multiplayer session.
- Allow players to join.
- Run or play the session.

### Player

- Join a session.
- Interact with the game.
- Complete the multiplayer experience.

## Required Initial Capabilities

- Google sign-in.
- Game creation.
- AI-assisted creation from creator intent.
- Templates as useful starting points for creation.
- Preview/testing of generated games.
- Iterative refinement.
- Publishing.
- Public game discovery/search.
- Multiplayer session creation and play.
- Player joining and interaction.

Templates must not define the expressive limits of Playhoot.

## Game Expressivity Target

- The product should not validate its language only with quiz-style games.
- For the V1 product capability target, Playhoot should cover a spectrum from simple quizzes through substantially stateful, turn-based/card/board games with complexity roughly comparable to mechanics found in games such as Parques, UNO, or poker.
- This is a capability and expressivity target.
- It does not mean those exact games must ship in the initial public catalog.
- It does not mean Monopoly-scale rule/content complexity must be supported in V1.

## Explicitly Not Required for Initial Launch

- Active paid billing mechanics.
- Final monetization policy.
- A complete catalog for every possible social-game audience.
- Launching couples-oriented experiences as the primary positioning.
- Launching general social/party games as the primary positioning.
- Monopoly-scale rule/content complexity.

## Open Product Decisions

These questions are unresolved. They are not necessarily launch blockers.

- Exact minimum creation wizard.
- Exact initial template catalog.
- Asset generation/upload experience.
- Content moderation and safety for public user-created/discoverable content.
- Supported room-size limits.
- Exact mobile/desktop requirements.
- Remixing behavior.
- Monetization policy and mechanics.
