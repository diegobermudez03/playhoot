## Current Gaps

- Game Management lifecycle operations beyond retrieving a playable game (by current version or by a pinned Definition/Version UUID) were not found implemented.
- Session Runtime does not yet return or persist 7 of the engine's 9 committed `Output` variants (everything except Open/CloseQuestion) - timers, effects, presentations, and workflow completion are silently dropped after a RuntimeTurn drains. This is the current, immediate gap: `docs/projects/active/session-runtime-v1/PROJECT.md`'s Phase 1 exists specifically to close it before any live-transport fan-out is rebuilt on top of it.
- `api`'s HTTP/WebSocket transport exists as a skeleton (real routes, a real connection upgrade) but calls no domain package - see the Session Runtime row above and `docs/projects/active/session-runtime-v1/works/WORK-0005-thin-live-coordinator.md`'s Blocker 11.
- Session Runtime timer obligations, the `session_runtime_failures` diagnostic entity, disconnect/reconnect/resync, and `activity_expires_at` inactivity expiration are not yet implemented. `activity_expires_at` in particular has no schema/enforcement anywhere yet despite being already-accepted architecture (`game/README.md`'s Durable Inactivity Expiration section) - AnswerInteraction is the first RUNNING-phase mutation this could apply to, but WORK-0004 did not add it, consistent with Start never having added it either; flagged here as a pre-existing gap, not a regression.
