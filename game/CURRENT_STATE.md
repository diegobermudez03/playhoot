## Current Gaps

- Game Management lifecycle operations beyond retrieving a playable game (by current version or by a pinned Definition/Version UUID) were not found implemented.
- Session Runtime returns Question (persisted), Effect, and Presentation Outputs (in memory only) from `Start`/`AnswerInteraction`, terminalizes the Session on a game-completion Output (`TerminalReasonGame*`), and now durably persists/expires timer obligations (WORK-0012, IMPLEMENTING - real-Postgres verification and independent review outstanding). Nothing yet consumes the returned Effect/Presentation Outputs, the game-completion fact, or physically schedules a timer obligation's expiration: no live-transport Coordinator exists to fan any of them out to a connected client or call `Manager.ExpireTimer` from a real wall-clock event - `docs/projects/active/session-runtime-v1/works/WORK-0020-role-aware-live-connections.md` owns rebuilding that Coordinator.
- `api`'s HTTP/WebSocket transport exists as a skeleton (real routes, a real connection upgrade) but calls no domain package - see the Session Runtime row above and `docs/projects/active/session-runtime-v1/works/WORK-0005-thin-live-coordinator.md`'s Blocker 11.
- Session Runtime's `session_runtime_failures` diagnostic entity, disconnect/reconnect/resync, and `activity_expires_at` inactivity expiration are not yet implemented. `activity_expires_at` in particular has no schema/enforcement anywhere yet despite being already-accepted architecture (`game/README.md`'s Durable Inactivity Expiration section) - AnswerInteraction is the first RUNNING-phase mutation this could apply to, but WORK-0004 did not add it, consistent with Start never having added it either; flagged here as a pre-existing gap, not a regression.

Behavior shared by two or more of this workflow's steps lives under its own `internal/<mechanism-name>/` subpackages, sibling to `internal/repo/`: `internal/interactions/` records every Turn's `OpenQuestionOutput`/`CloseQuestionOutput` as `session_interactions` rows, `internal/timers/` records every Turn's `Schedule(Keyed)TimerOutput`/`Cancel(Keyed)TimerOutput` as `session_timer_obligations` rows (both called by `step_start.go`/`step_answer_interaction.go`/`step_expire_timer.go`), `internal/clientoutputs/` selects the same Turn's Effect/Presentation Outputs for the caller, `internal/completion/` detects a `RunCompletedOutput` and maps it to the matching `TerminalReasonGame*` value, and `internal/expiration/` materializes lazy lobby expiration (called by `step_join.go`/`step_leave.go`/`step_start.go`). `outputs.go`, in the `sessionlifecycle` package itself rather than a further `internal/` subpackage, declares this package's own exported `Output`/`Value` schema and `(*Manager).mapOutputs`, which needs `Manager`'s own repository access to resolve recipient identity.
- Session Runtime shared lobby mechanics: `game/session/internal/sessionlock/` (locked-row fact reporting only - expiration policy itself is Manager-owned, see `internal/expiration/`), `game/session/internal/idempotency/` (claim/replay mechanics - replay/conflict/new-command policy itself is Manager-owned, see each step's own `step_create.go`/`step_join.go`/`step_leave.go`/`step_start.go`). Both mechanism packages are called directly by the Manager's steps, not through repository forwarding methods. Actor/Participant persistence lives in `internal/repo/` and is consumed by all four steps through step-local narrow interfaces (not a shared horizontal entity package).
- Game Language v1 implementation and tests: `game/language/v1/program/` and `game/language/v1/engine/`.
